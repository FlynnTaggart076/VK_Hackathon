# Change request: пошаговый диалог и контакты по адресу дома

Решение владельца 2026-09-29. Дополняет [change-request-deepseek.md](change-request-deepseek.md). Не развёрнуто на VM: развёртывание выполняется отдельно из принятого SHA по §12.8 ТЗ.

## Что было сломано

- Бот бесконечно переспрашивал территорию. `assistant_adapter.answer_json` перезаписывал уточнённую территорию значением из профиля. Чат понимал ответы только про услугу и вид документа. Варианты ответа в чате не показывались.
- «Контакт поставщика», «контакты УК», «передать показания» при реальном регионе всегда заканчивались «пока нет проверенного ответа». Местных источников и организаций в `knowledge/` нет, а поиска по адресу не было.
- Мини-приложение:
  - теряло тему, найденную сервером;
  - переносило старые уточнения в новый вопрос;
  - для ответа на уточнение территории перезаписывало профиль и сбрасывало согласие на городскую статистику.
- DeepSeek в чате фактически не работал: только через `/llm_on`, без контекста диалога, ошибки не логировались.

## Что сделано

- **Общий серверный диалог** `apps/backend/app/services/dialog.py`:
  - используется и в чате MAX, и в мини-приложении (`POST /api/v1/assistant/dialog`);
  - состояние хранится в таблице `dialog_states`, миграция `e5_dialog_state`: тема, услуга, город, адрес, выбранный дом, ожидаемое уточнение, предложенные варианты;
  - ответ на уточнение принимается кнопкой, её номером или обычным текстом («Москва», «в Люберцах», «холодная вода», «собственник»);
  - новый вопрос посреди сценария сбрасывает сценарий, а город и дом запоминаются на 30 дней.
- **Контакты по адресу** `apps/backend/app/services/house_lookup.py`. Это порт консольного прототипа `colleague_anton/research/house_lookup.py`:
  - HouseScore даёт дом, управляющую организацию и её телефон и почту;
  - Dominfo даёт исторических поставщиков по услугам;
  - `knowledge/house_lookup/organization_contacts.json` даёт сайты поставщиков только по точному ИНН с подтверждающей ссылкой.

  Сценарий: услуга → адрес → выбор дома или корпуса → карточка. После карточки доступны «Другая услуга», «Другой адрес», «Новый вопрос». Для показаний, сроков и проблем с услугой перед карточкой выводится общее пояснение.
- **Бот:**
  - варианты ответа приходят кнопками MAX типа `message`, ссылки — кнопками типа `link`;
  - внешние вызовы (HouseScore, Dominfo, DeepSeek) выполняются вне транзакции очереди;
  - сбой отдельного ответа не блокирует очередь.
- **DeepSeek:**
  - после явного согласия одной кнопкой («Включить умные ответы» / «Без нейросети») или `/llm_on`, `/llm_off` модель `extract()` разбирает реплику с учётом диалога;
  - за один ход модель вызывается не больше одного раза;
  - адрес, номера, телефоны и почта в модель не передаются;
  - причины сбоя логируются кодом, без содержимого.

## Решения владельца и отступления от ТЗ v1.1

- **HouseScore:** документированный API с ключом, квота около 100 запросов на ключ.
- **Dominfo:** внутренние недокументированные JSON-методы сайта. ТЗ §2.3 их исключает; владелец принял это решение осознанно. Сведения Dominfo помечаются как исторические («действующий договор не проверен»), а при недоступности источника карточка УК сохраняется.
- **Приватность:**
  - адрес дома без квартиры и лицевого счёта уходит только в HouseScore и Dominfo, об этом сказано прямо в вопросе об адресе;
  - номер квартиры, лицевой счёт, телефон и почта вырезаются до запроса;
  - URL поиска и адреса не логируются;
  - файлы кэша поиска удаляются через 30 дней, состояние диалога — через 30 дней бездействия.
- **Квоты:**
  - `HOUSESCORE_DAILY_LIMIT` (по умолчанию 30 живых запросов в сутки на весь стенд);
  - `HOUSE_LOOKUP_USER_DAILY_LIMIT` (5 новых адресов в сутки на пользователя);
  - ответы кэшируются в `STORAGE_PATH/house_cache`: HouseScore на 7 дней, Dominfo на 30 дней;
  - при сбое сети используется устаревший кэш.
- **Движок и замороженные наборы вопросов не менялись:**
  - контактные темы диалог сам отправляет в поиск по адресу;
  - в `knowledge/sources.yaml` добавлены два общих источника ГИС ЖКХ (карточка дома и поиск по адресу, проверены 2026-09-29) для ответа, когда поиск недоступен.

## Развёртывание

1. В приватный `runtime/app.env` production добавить `HOUSESCORE_API_KEY=<ключ ZK_API>`. Для preview ключ принудительно пустой (`compose.preview.vm.yaml`).
2. Необязательно: чтобы демонстрационные дома не тратили квоту, скопировать сохранённые ответы прототипа (`colleague_anton/research/house_lookup_cache/*.json`, без `live_requests.json`) в том `source_documents` по пути `/storage/house_cache/` и назначить владельца `app:app`. Эти файлы содержат реальные адреса домов, поэтому в Git не публикуются.
3. Миграция `e5_dialog_state` выполняется сервисом `migrate`. Readiness ожидает именно эту ревизию.
