# E4 preview: синтетическая приёмка

Проверять **только** изолированный `/team/zhkh-preview/`. Скрипт отказывается от другого пути, от публичного HTTP и от URL с query/fragment. Он создаёт двух новых виртуальных гостей через `POST /api/v1/auth/preview`, записывает синтетические образцы в preview БД, проверяет разделение данных, затем удаляет созданные черновик и квитанции. Токены и ID пользователей не выводятся. Если проверка упадёт до очистки, в preview могут остаться созданные синтетические записи; их можно удалить из истории того же гостя лишь до истечения сессии. Не запускайте против production.

```powershell
$env:PREVIEW_BASE_URL = 'https://flynntaggart075.asuscomm.com/team/zhkh-preview/'
python packages/housing_engine/preview_acceptance.py
Remove-Item Env:PREVIEW_BASE_URL
```

В изолированном локальном Compose допускается `http://127.0.0.1:<port>/team/zhkh-preview/`. Скрипт использует только стандартную библиотеку Python; секреты и настоящие документы ему не нужны. Он проверяет:

1. Режим `preview`, реальный engine и выключенные голос/внешнюю отправку.
2. Два независимых guest ID, первый запуск: `moscow` и `moscow-oblast`, подтверждение уведомления о данных.
3. Отказ `403 PREVIEW_SYNTHETIC_ONLY` на байтовую загрузку даже синтетического PDF. Затем серверный импорт `water-2026-08` и `water-2026-09`, проверку и подтверждение человеком. Это **JSON demo import**, а не OCR файла.
4. Объяснение 200.00 ₽; сравнение 200.00 → 270.00 ₽, разница 70.00 ₽ = 40.00 ₽ объём + 30.00 ₽ тариф по заранее заданному `fixtures/receipts/water-comparison.json`.
5. Общий ответ про лицевой счёт, неизвестный вопрос и запрос программного кода вне предметной области. В последних двух случаях ожидается честное `unsupported` без выдуманного источника.
6. Черновик с проверенным числом 270.00 ₽, ручную правку, отсутствие установленного получателя и действия отправки.
7. Историю, `404 NOT_FOUND` на квитанцию/ответ/черновик/сравнение другого гостя, удаление записей владельцем.

## Ручная браузерная проверка

Автоматический HTTP smoke не проверяет интерфейс. Откройте preview из обычного браузера на 360 px и на широком экране:

| Шаг | Ожидание |
|---|---|
| Открыть URL в чистом профиле | Экран приложения появляется без MAX и без ввода кода; заметна метка учебного режима. |
| Выбрать Москву или МО, роль и подтвердить уведомление | Выбранный профиль сохраняется, пользователь видит синтетические ограничения. Местная УК не подставлена и не объявлена проверенной. |
| Импортировать «Вода, август», затем «Вода, сентябрь» | Оба образца помечены синтетическими, поля требуют проверки человеком, суммы 200/270 ₽. |
| Подтвердить оба образца, открыть историю и сравнить | Видны 70/40/30 ₽ и отсутствие утверждения о нарушении/переплате. |
| Задать «Где найти лицевой счёт?», «xyzzy неизвестное», «Напиши функцию сортировки списка на Python» | Первый ответ общий с источником; второй и третий признают отсутствие проверенного ответа. |
| Подготовить черновик запроса расшифровки | Текст можно изменить и скопировать; отправка не предлагается и не происходит. |
| Открыть приватное окно как второй гость | Нет истории, ответов и черновиков первого; прямые ссылки первого не открываются. |
| Удалить документ из истории | Он исчезает; повторное открытие прямой ссылки даёт отсутствие записи. |

Запишите фактический release SHA, дату, браузер/устройство, ширину, шаг, ожидаемое и фактическое поведение. Отмечайте отдельно `HTTP`, `браузер`, `VM HTTPS`, `MAX Web` и `MAX mobile`. Проход preview не доказывает подписанный MAX `initData`, доставку сообщений бота или точность OCR реальных квитанций. Для проверки байтового OCR используйте отдельно только разрешённые синтетические PDF/PNG из `fixtures/receipts/manifest.json` и указывайте это как синтетический OCR.
